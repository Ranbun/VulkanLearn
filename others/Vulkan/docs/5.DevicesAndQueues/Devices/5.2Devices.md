## 逻辑设备

&ensp;&ensp;设备对象代表与物理设备的逻辑连接。每个设备公开多个队列族，每个队列族有一个或多个队列。队列族中的所有队列支持相同的操作。<br>
&ensp;&ensp;如前面的“物理设备”一节所述，`Vulkan`应用程序首先会查询系统中的所有物理设备。然后可以查询每个物理设备的功能，包括其队列和队列族属性。一旦确定了可接受的物理设备，应用程序将创建相应的逻辑设备。创建的逻辑设备随后成为与物理设备进行交互的主要接口。<br>
&ensp;&ensp;如何枚举系统中的物理设备并查询这些物理设备的队列族属性在上面的“物理设备枚举”部分中有描述。<br>
&ensp;&ensp;如果这些物理设备属于同一设备组，则可以从多个物理设备创建单个逻辑设备。设备组是一组支持相互访问内存并在所有物理设备上记录单个命令缓冲区的物理设备。通过调用`vkEnumeratePhysicalDeviceGroups`来枚举设备组，并通过`VkDeviceGroupDeviceCreateInfo`将物理设备传递给设备组中的子集，可以从设备组中的多个物理设备创建逻辑设备。为了使两个物理设备属于同一设备组，它们必须支持相同的扩展、功能和属性。

<p style="color: #707070" Size=10>
    <font color=red Size=4>Notes</font>:<br>
    &ensp;&ensp;在同一设备组中的物理设备必须非常相似，因为没有规定不同功能或属性之间的交互规则。它们必须对几乎所有不变的功能、属性、能力等返回相同的值，但可能在某些查询上有所不同，比如连接了不同的显示器或使用了不同的合成器。规范没有尝试枚举每个状态属于哪个类别，因为这样的列表很快就会过时。使用vkGetPhysicalDevice*函数可以查询物理设备的属性和功能信息。
 </p>

&ensp;&ensp;要获取系统中存在的设备组列表，调用以下函数：<br>

```C++
// Provided by VK_VERSION_1_1
VkResult vkEnumeratePhysicalDeviceGroups(
    VkInstance                                  instance,   // a handle to a Vulkan instance
    uint32_t*                                   pPhysicalDeviceGroupCount, //一个指向整数的指针
    VkPhysicalDeviceGroupProperties*            pPhysicalDeviceGroupProperties //一个指向VkPhysicalDeviceGroupProperties结构数组的指针
);

// instance must be a valid VkInstance handle
// pPhysicalDeviceGroupCount must be a valid pointer to a uint32_t value
```



### 5.2.1 创建设备

&ensp;&ensp;逻辑设备使用`VkDevice`句柄表示

```C++
// Provided by VK_VERSION_1_0
VK_DEFINE_HANDLE(VkDevice)
```

&ensp;&ensp;创建一个逻辑设备是用来连接物理设备的，要创建逻辑设备调用以下函数：

```C++
// Provided by VK_VERSION_1_0
VkResult vkCreateDevice(
    VkPhysicalDevice                            physicalDevice,  // 选择的物理设备
    const VkDeviceCreateInfo*                   pCreateInfo,
    const VkAllocationCallbacks*                pAllocator,
    VkDevice*                                   pDevice);

```

- `physicalDevice`参数必须是`vkEnumeratePhysicalDevices`函数返回的句柄之一
- `pCreateInfo`参数是一个指向`VkDeviceCreateInfo`结构体类型的指针
- `pAllocator`内存分配器
- `pDevice`一个`VkDevice`类型的指针，用于返回创建的逻辑设备

&ensp;&ensp;`vkCreateDevice`函数会验证在`pCreateInfo`的`ppEnabledExtensionNames`和`pEnabledFeatures`成员中请求的扩展和特性是否被实现支持。如果有任何请求的扩展不被支持，`vkCreateDevice`将返回`VK_ERROR_EXTENSION_NOT_PRESENT`。如果有任何请求的特性不被支持，`vkCreateDevice`将返回`VK_ERROR_FEATURE_NOT_PRESENT`。在创建设备之前，可以通过查询`vkEnumerateDeviceExtensionProperties`来检查扩展的支持情况。类似地，可以通过查询`vkGetPhysicalDeviceFeatures`来检查特性的支持情况。<br>

&ensp;在验证和启用扩展后，`VkDevice`对象将被创建并返回给应用程序。

&ensp;&ensp;可以从同一物理设备创建多个逻辑设备。逻辑设备的创建可能由于缺乏设备特定资源而失败（除其他错误之外）。如果发生这种情况，`vkCreateDevice`将返回`VK_ERROR_TOO_MANY_OBJECTS`。

### 5.2.3. 设备丢失

&ensp;&ensp;逻辑设备可能因为一些特定于实现的原因而丢失，这意味着挂起和未来的命令执行可能会失败，并导致资源和支持内存的状态变得不确定

<p style="color: #707070" Size=10>
    <font color=red Size=4>Notes</font>:<br>
    &ensp;&ensp;设备丢失的典型原因可能包括执行超时（以防止拒绝服务攻击）、电源管理事件、平台资源管理以及实现错误。<br>
    &ensp;&ensp;如果应用程序不遵守有效用法，也可能导致报告设备丢失，但这并不是绝对的。即使报告了设备丢失，系统可能处于不可恢复的状态，继续使用 API 仍被视为无效。
 </p>
&ensp;&ensp;当发生这种情况时，某些命令将返回VK_ERROR_DEVICE_LOST。在任何这样的事件之后，逻辑设备被认为是丢失的。无法将逻辑设备重置为非丢失状态，但丢失状态仅适用于逻辑设备（VkDevice），相应的物理设备（`VkPhysicalDevice`）可能不受影响。<br>
&ensp;&ensp;在某些情况下，物理设备可能也会丢失，并且尝试创建新的逻辑设备将失败，返回`VK_ERROR_DEVICE_LOST`。这通常表明底层实现或其与主机的连接存在问题。如果物理设备尚未丢失，并且成功从该物理设备创建了新的逻辑设备，则该逻辑设备必须处于非丢失状态。

<p style="color: #707070" Size=10>
    <font color=red Size=4>Notes</font>:<br>
    &ensp;&ensp;尽管逻辑设备丢失可能是可恢复的，但在物理设备丢失的情况下，除非系统上存在其他未受影响的物理设备，否则应用程序可能无法恢复。该错误主要用于信息目的，仅用于通知用户发生了平台问题，并应进一步调查。例如，底层硬件可能出现故障或与系统的其余部分物理断开连接。在许多情况下，物理设备丢失可能导致其他更严重的问题，例如操作系统崩溃；在这种情况下，可能不会通过Vulkan API报告。
 </p>

&ensp;&ensp;当设备丢失时，其子对象并不会被自动销毁，它们的句柄仍然有效。在销毁设备或其父对象之前，这些子对象必须手动进行销毁（请参阅"对象生命周期"部分）。通过`vkMapMemory`映射的设备内存对应的主机地址空间仍然有效，对这些映射区域的主机内存访问仍然有效，但映射区域的内容变为未定义状态。在设备丢失的情况下，仍然可以对设备及其子对象调用任何`Vulkan API`命令。

一旦设备丢失，命令执行可能失败，并且某些返回`VkResult`的命令可能返回`VK_ERROR_DEVICE_LOST`错误代码。这些命令可以在每个命令的"返回代码"部分中识别出来，其中包含了`VK_ERROR_DEVICE_LOST`。不允许运行时错误的命令仍必须对有效用法正确执行，并在适用情况下返回有效数据

&ensp;&ensp;对于那些无限等待设备执行的命令（特指`vkDeviceWaitIdle，vkQueueWaitIdle`，带有最大超时的`vkWaitForFences`，以及在`flags`中设置了`VK_QUERY_RESULT_WAIT_BIT`位的`vkGetQueryPoolResults`），即使设备丢失，它们必须在有限时间内返回，返回值要么是`VK_SUCCESS`，要么是`VK_ERROR_DEVICE_LOST`。对于可能返回`VK_ERROR_DEVICE_LOST`的任何命令，在确定命令缓冲区是否处于挂起状态或设备是否正在使用资源时，`VK_ERROR_DEVICE_LOST`的返回值与`VK_SUCCESS`是等效的。

在设备丢失后，从丢失设备导出或导入的任何外部内存对象的内容将变得未定义。其他逻辑设备或其他API中与丢失设备上的外部内存对象关联的相同底层内存资源的对象不受影响，除非它们的内容变得未定义。与丢失设备上的外部内存对象关联的`VkDeviceMemory`对象上绑定的其他逻辑设备上图像的子资源布局将变为`VK_IMAGE_LAYOUT_UNDEFINED`。

从丢失设备导出的具有临时永久性的信号量载荷所创建的其他逻辑设备上的`VkSemaphore`对象的状态是未定义的。与丢失设备上的`VkSemaphore`对象永久共享信号量载荷的其他逻辑设备上的`VkSemaphore`对象的状态也是未定义的，并且在随后的任何信号操作后仍然保持未定义状态。实现必须确保对此类信号量的待定和随后提交的等待操作的行为与外部信号量的等待操作的状态要求中定义的行为一致。

### 5.2.4. 设备的销毁

调用函数以销毁设备：

```C++
// Provided by VK_VERSION_1_0
void vkDestroyDevice(
    VkDevice                                    device,  //被销毁的设备
    const VkAllocationCallbacks*                pAllocator  // 分配器
);
```

为确保设备上没有正在执行的工作，可以使用`vkDeviceWaitIdle`来限制设备的销毁。在销毁设备之前，应用程序负责销毁/释放使用该设备作为对应的`vkCreate*或vkAllocate*`命令的第一个参数创建的任何`Vulkan`对象。

<p style="color: #707070" Size=10>
    <font color=red Size=4>Notes</font>:<br>
    &ensp;&ensp;每个对象的生命周期都受到VkDevice对象的限制。因此，为了避免资源泄漏，应用程序在调用vkDestroyDevice之前必须明确释放所有这些资源。
 </p>

- 所有`Device`的子对象的销毁必须在`Device`对象被销毁前完成
- 如果在创建设备时提供了`VkAllocationCallbacks`，那么在这里必须提供与之兼容的回调函数。
- 如果在创建设备时没有提供`VkAllocationCallbacks`，那么`pAllocator`必须为`NULL`。

#### 主机同步：

- 主机对设备的访问必须进行外部同步。

- 主机对由设备创建的所有`VkQueue`对象的访问也必须进行外部同步。
