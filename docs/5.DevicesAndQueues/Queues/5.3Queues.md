# Queues

### 5.3.1. 队列族属性 Queue Family Properties

如前面在“物理设备枚举”部分所讨论的那样，使用`vkGetPhysicalDeviceQueueFamilyProperties`命令可以获取有关设备支持的队列族和队列的详细信息。

`vkGetPhysicalDeviceQueueFamilyProperties`返回的`pQueueFamilyProperties`数组中的每个索引描述了该物理设备上的一个唯一队列族。这些索引在创建队列时使用，并且它们直接对应于通过`VkDeviceQueueCreateInfo`结构传递给`vkCreateDevice`命令的`queueFamilyIndex`，如下文“队列创建”部分所述。

物理设备内部对队列族的分组是由实现（`Vulkan`驱动和硬件）决定的。

<p style="color: #707070" Size=10>
    <font color=red Size=4>Notes</font>:<br>
    &ensp;&ensp;通常情况下，物理设备会将所有具有相同功能的队列分组到一个队列族中。然而，尽管实现应该这样做，但也有可能物理设备返回两个具有相同功能的独立队列族。
 </p>

一旦应用程序已经确定了具有所需队列的物理设备，它将与逻辑设备一起创建这些队列。这将在接下来的章节中描述。

### 5.3.2. 创建队列 Queue Creation

创建逻辑设备也会创建与该设备相关联的队列。要创建的队列由一组`VkDeviceQueueCreateInfo`结构描述，在调用`vkCreateDevice`时作为`pQueueCreateInfos`参数传递进去

队列通过`VkQueue`句柄来表示：

```C++
// Provided by VK_VERSION_1_0
VK_DEFINE_HANDLE(VkQueue)
```



### 5.3.3. 队列族索引 Queue Family Index

在`Vulkan`中，队列族索引在多个地方被使用，用于将操作绑定到特定的队列族。

当通过`vkGetDeviceQueue`获取队列的句柄时，队列族索引用于选择从中检索`VkQueue`句柄的特定队列族，如前面的部分所述。

在创建`VkCommandPool`对象时（参见`Command Pools`），在`VkCommandPoolCreateInfo`结构中指定了一个队列族索引。从此池中获取的命令缓冲区只能提交到与该队列族对应的队列上。

在创建`VkImage`（参见`Images`）和`VkBuffer`（参见`Buffers`）资源时，`VkImageCreateInfo`和`VkBufferCreateInfo`结构中包含了一组队列族，用于指定可以访问该资源的队列族。

在插入`VkBufferMemoryBarrier`或`VkImageMemoryBarrier`（参见`Pipeline Barriers`）时，会指定源队列族索引和目标队列族索引，以允许将缓冲区或图像的所有权从一个队列族转移到另一个队列族。有关详细信息，请参阅资源共享部分。

### 5.3.4. 队列优先级 Queue Priority

每个队列都被分配了一个优先级，这是在创建设备时通过`VkDeviceQueueCreateInfo`结构设置的。每个队列的优先级是一个取值在0.0到1.0之间的标准化浮点数，然后由实现将其转换为离散的优先级级别。较高的值表示较高的优先级，其中0.0表示最低优先级，而1.0表示最高优先级。

在同一个设备内，优先级较高的队列可能会被分配比优先级较低的队列更多的处理时间。实现对于具有相同优先级的队列之间的排序或调度没有任何保证，除非由任何显式的同步原语定义的约束。实现对于跨不同设备的队列也没有任何保证。

实现可能允许优先级较高的队列在同一个 `VkDevice `上饿死优先级较低的队列，直到优先级较高的队列没有更多的命令可以执行为止。队列优先级的关系不应导致一个 `VkDevice `上的队列饿死另一个 `VkDevice` 上的队列。换句话说，优先级的影响范围限定在同一个 `VkDevice` 内部，不会影响到其他 `VkDevice` 上的队列

没有对优先级较高的队列获得更多处理时间或比优先级较低的队列提供更好服务质量的具体保证。实现对优先级的处理可能因设备和驱动的不同而有所差异，优先级只是用于提供一种相对的指导，而并非绝对的保证。因此，应用程序不能依赖于队列优先级来实现特定的行为，而应该使用显式的同步机制来确保正确的执行顺序和资源共享。

### 5.3.5. 队列提交 Queue Submission

在`Vulkan`中，工作是通过将命令记录到命令缓冲区中，并提交给队列来执行的。队列提交是将命令缓冲区中的命令提交到设备的执行引擎执行的过程。队列提交命令通常采用`vkQueue*`的形式（例如`vkQueueSubmit`、`vkQueueBindSparse`等），并且可以携带一个信号量列表，用于在工作开始前等待，以及一个信号量列表，用于在工作完成时发出信号。工作本身以及信号量的等待和发出都是队列操作。队列提交命令在提交队列操作后会将控制权返回给应用程序，不会等待操作完成。

通过队列提交，应用程序可以将多个命令缓冲区提交到一个或多个队列，以并行地执行不同的任务。由于`Vulkan`设备的深度流水线和并行处理能力，实现有很大的自由度来重叠和并行执行提交到队列的工作。

队列提交命令返回控制权给应用程序后，命令缓冲区中的命令将开始执行，并在不需要进一步的应用程序干预的情况下完成执行。但是，这些命令的执行顺序受到多个隐式和显式的排序约束的影响。对于不同队列之间的队列操作或与主机之间的队列操作之间没有隐式的排序约束，因此它们可以以任意顺序执行。但是，可以通过使用信号量和栅栏等显式的同步机制来定义队列之间的执行顺序和依赖关系。

在`Vulkan`中，工作是通过队列提交命令（如`vkQueueSubmit2`或`vkQueueSubmit`）提交到队列中的。这些队列提交命令定义了一组要由底层物理设备执行的队列操作，包括与信号量和栅栏进行同步。通过这些命令，应用程序可以将工作任务分批提交到一个或多个队列，以并行地执行不同的任务。底层物理设备的深度流水线和并行处理能力使得实现有很大的自由度来重叠和并行执行提交到队列的工作。一旦队列提交命令返回控制权给应用程序，提交到队列中的工作将开始执行，并在不需要进一步的应用程序干预的情况下完成执行。

提交命令接受目标队列、零个或多个工作批次以及一个可选的栅栏作为参数，用于在完成时发出信号。每个批次由三个不同的部分组成：

- 在执行批次的其余部分之前，会等待零个或多个信号量
  - 如果存在，这些信号量描述了一个信号量等待操作。
- 有零个或多个要执行的工作项。
  - 如果存在，这些工作项描述了匹配所描述工作的队列操作。

- 还有零个或多个在工作项完成后要发出信号的信号量。
  - 如果存在，这些信号量描述了一个信号量信号操作。

如果在队列提交中存在一个栅栏，它描述了一个栅栏的信号操作。

在命令返回之前，所有在队列提交命令中描述的工作必须提交到队列中。

#### 稀疏内存绑定 Sparse Memory Binding

在`Vulkan`中，可以通过稀疏资源章节中所描述的方式，将内存稀疏地绑定到缓冲区和图像。稀疏内存绑定是一个队列操作。包含`VK_QUEUE_SPARSE_BINDING_BIT`标志的队列必须能够支持将虚拟地址映射到设备上的物理地址。这会导致设备上的页表映射更新。为了避免在图形命令执行期间破坏页表映射，这个更新必须在队列上同步。通过在队列上绑定稀疏内存资源，所有依赖于更新绑定的命令都会在绑定更新之后同步执行。在Synchronization and Cache Control章节中可以了解到如何实现这种同步。

### 5.3.6. 队列销毁 Queue Destruction

队列是在调用`vkCreateDevice`时与逻辑设备一起创建的。当调用`vkDestroyDevice`销毁该设备时，与逻辑设备相关联的所有队列也会被销毁。
